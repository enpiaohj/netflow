# NetFlow 设计变更说明 v1.1

本文记录相对《NetFlow 完整产品设计与技术实施方案 v1.0》（以下简称“设计 v1.0”）在 v0.2.0、v0.3.0 中发生的设计与架构变更，说明变更原因、实现方式和影响范围。设计 v1.0 保持不变，发生冲突时以本文为准。

## 2. 详细变更

### C1 抓包进程自宿主

**背景**：设计 v1.0 采用独立的 `NetFlow.CaptureHost.exe` 作为一次性提权子进程。单文件发布时，宿主必须与主程序放在同一目录，否则提示“采集宿主缺失”，单个 exe 无法抓包。

**方案**：主程序以 `--capture-host --params <参数文件>` 参数，经 UAC 以管理员身份重新启动自身。此模式下 `App.OnStartup` 直接执行抓包逻辑（`CaptureHostProgram`，已移入 `NetFlow.Capture`），不创建窗口，也不初始化数据库等应用服务，完成后以退出码结束进程。

**安全约束不变**：

- 抓包进程只接受经校验的参数文件（`CaptureParams.Validate`）：任务 ID 格式、IP 合法性、时长与截断范围、工作目录存在，且参数文件必须位于工作目录内（限定写入范围）。
- 主程序仍以标准权限运行；提权仅发生在抓包进程。
- 停止通道保持“命名事件 + 停止文件”双通道。

**兼容**：`NetFlow.CaptureHost` 项目保留，同目录存在独立宿主时仍可使用（`PktmonCaptureController` 支持自定义宿主路径与参数前缀）。

### C2 实时显示

**方案**：宿主执行 `pktmon start --capture --pkt-size N --log-mode real-time`，读取其标准输出并逐行写入任务目录的 `live.log`；界面每 500 毫秒读取新增内容，经 `PktmonLiveParser` 解析后追加到列表。

| 项 | 设计 |
|---|---|
| 编码 | 输出含本地化文字，宿主与界面均按 Latin-1 逐字节读写；解析只依赖 ASCII 片段（时间、Tx/Rx、地址、协议）。 |
| 去重 | Pktmon 在协议栈多个组件处重复输出同一数据包。同方向、内容相同、间隔不超过 5 毫秒的输出视为同一数据包。 |
| 解析 | 头部行：时间、方向；详情行：`SRC.port > DST.port: 协议信息`。识别 TCP（标志、seq、win、len）、UDP、DNS（端口 53）、ICMP/ICMPv6、ARP。 |
| 限制 | `live.log` 最大 64 MB，超出后不再落盘；界面列表最多 20000 行，超出后统计继续。 |
| 缓冲文件 | 实时模式仍会创建 ETL 缓冲文件（默认 `PktMon.etl`，最大 512 MB，位于进程工作目录）。已限定为任务目录内的 `live-buffer.etl`、最大 16 MB，停止后删除。 |
| 产物 | 不生成 PCAPNG；状态文件记录 `Mode = live`。 |

“记录后分析”方式不变，并新增自动停止：到达最长时长后 2 秒，界面自动执行停止与分析流程。

### C3 源网卡

**规则**：

1. 测试必须有明确的源网络，取消“自动”选项。
2. 默认源网卡：带默认网关的以太网卡；其次带网关的无线、其他网卡；再次任一可用网卡。排序稳定，同级保持系统枚举顺序。
3. 候选网卡：在线、非回环、至少有一个可用地址（排除 IPv4 169.254/16 与 IPv6 链路本地地址）。
4. 每次使用时按网卡名重新读取地址，避免 DHCP 变更后使用旧地址；网卡不可用或没有与目标同协议族的地址时报错，不静默回退。
5. 选择持久化；网卡断开时恢复默认并提示。

**探针行为**：

- 绑定源地址的检查：TCP、UDP、DNS、TLS、HTTP、SMTP、SMB、SSH、RDP、NTP、WinRM 的 TCP 阶段。
- ICMP：.NET `Ping` 无法指定源地址，v0.2.0 曾把“请求的源地址”写入证据，属证据失真。v0.3.0 改用 `iphlpapi.dll` 的 `IcmpSendEcho2Ex` 真正绑定源地址（仅 IPv4 源与 IPv4 目标）；不能绑定时记录限制且不写入源地址。
- 无法绑定：LDAP 绑定与查询、SQL 登录阶段、WinRM 的 HTTP 请求阶段。通过 `NoteSourceNotBindable` 统一记录“限制：……无法指定源地址，本次由系统路由选择”。
- 编排器优先选择与源地址同协议族的解析结果；持续监测按网卡名在每次采样时取地址。

### C4 数据存储（schema v2）

设计 v1.0 7.2 的“单连接 + 单写队列 + 迁移”保持不变。`DiagnosisRepository` 改为 partial 类，新增应用数据表，迁移只增表、不动旧表，可重复执行。

| 表 | 结构 | 用途 |
|---|---|---|
| `app_settings` | `key` 主键、`value`、`updated_utc` | 键值设置。`app.settings` 存应用设置 JSON；`ui.source-adapter`、`pref.*` 存界面偏好。 |
| `port_packs` | `id` 主键、`name` 唯一、`description`、`entries`（文本）、`updated_utc` | 自定义端口包。端口项以可读文本存储（如 `tcp/445 SMB`）。 |
| `recent_inputs` | `(kind, value)` 主键、`last_used_utc` | 各输入框的最近输入（每类最多 15 条）。 |
| `schema_version` | 版本 2 | 记录迁移版本。 |

**应用设置**（`AppSettings`，读取时自动修正越界值）：

| 字段 | 默认 | 范围 |
|---|---|---|
| DefaultTimeoutSeconds | 3 | >0 且 ≤60 |
| BatchConcurrency | 8 | 1–32 |
| CaptureMode | record | record / live |
| CaptureDurationSeconds | 120 | 10–3600 |
| CaptureSnapBytes | 128 | 0–1514 |
| RedactionEnabled | true | — |
| RetentionDays | 30 | 1–3650 |
| Ai.* | 见 C8 | — |

**设计要点**：

- `UiState` 提供同步接口（内存缓存 + 后台写入）；数据库不可用时降级为仅内存。写入顺序由调用时刻的时间戳决定。
- 旧版 `ui-state.json` 首次启动时一次性导入，导入后改名为 `.migrated`，不删除。
- API Key 仅以 DPAPI（当前用户）密文保存在 `app.settings` 中；无法解密时按“未设置”处理并提示重新输入。
- 留存清理仅由用户确认后执行，且只删除任务 ID（32 位十六进制）命名的证据文件夹。
- 未迁移：自定义场景模板仍存放于 `user-templates.json`，列入后续计划。

### C5 端口包

- 数据模型：`PortEntry(协议, 端口, 说明)`、`PortPack`；文本格式解析 `PortPackText`（支持 `tcp/445`、`udp:123`、`445/tcp`、注释、去重、按行报错，最多 200 项）。
- 内置 12 个端口包（`BuiltinPortPacks`），只读；自定义端口包由 `PortPackStore` 管理，名称唯一且不得与内置包重名。
- 批量展开：`PortPackExpander` 将“主机行 × 端口包”展开为检测项；`host:port` 仅测该 TCP 端口；IPv6 字面量按主机处理；单次最多 2000 项；同一主机只解析一次。
- UDP 检测项：端口 123 使用 NTP 协议检查，其他端口使用原始 UDP。

### C6 事件日志

- `EventFilterBuilder` 将级别、时间范围、事件 ID 组合为 XPath（如 `*[System[(Level=1 or Level=2) and (EventID=4625) and TimeCreated[timediff(@SystemTime) <= 3600000]]]`）。“信息”级别同时包含 Level=0（始终记录），否则安全审核事件查不到。
- 日志名预置带中文显示，解析时取括号内的实际名称。
- 权限不足、日志不存在、远程 RPC 不通分别给出对应提示。
- 远程查询所需端口：TCP 135、动态 RPC 端口 49152–65535；服务列表另需 TCP 445。提供“检测远程端口”（135 与 445）。

### C7 SQL Server 场景

v0.2.0 及之前，SQL 场景总是先通过 Browser（UDP 1434）发现端口，Browser 关闭或被拦截时直接“未确认”，未测试 TCP 1433。现改为：未指定实例名时按默认实例直接测试 TCP 1433；指定固定端口则测该端口；指定实例名才经 Browser 发现。输入解析见 `SqlTargetParser`。

### C8 AI 分析

**范围**：设计 v1.0 未包含。作为分析辅助新增，不参与结论判定：状态矩阵和报告仍以类型化结果为事实源。

**数据流**：

```
结果页 → AiPromptBuilder 构造上下文 → Sanitize（屏蔽敏感字段，可选 IPv4 占位符，限长）
      → 预览与确认窗口 → DeepSeekClient（HTTPS）→ 结果（本地还原占位符）→ 显示
```

| 项 | 设计 |
|---|---|
| 接口 | OpenAI 兼容：`POST {API 地址}/chat/completions`、`GET {API 地址}/models`；`Authorization: Bearer`。 |
| 地址校验 | 必须为 https；仅本机回环地址允许 http。 |
| 模型 | 现行 `deepseek-flash`、`deepseek-v4-pro`；旧名 `deepseek-chat/reasoner` 为兼容别名。设置页可从 `/models` 获取列表。 |
| 推理 | 现行模型会先输出推理内容。参数 `reasoning_effort`（low/high/max）控制强度，默认 low；`max_tokens` 默认 16384；`finish_reason = length` 时标记“已截断”，推理耗尽无正文时给出可操作提示。 |
| 提示词 | 系统提示词固化三条红线与输出结构（结论摘要、关键证据、可能原因、下一步排查、需补充的信息）。 |
| 发送内容 | 仅摘要文本，最长 14000 字符；不发送 PCAPNG。 |
| 脱敏 | 密码、令牌、Authorization 等键值与 Bearer 令牌始终屏蔽；可选把 IPv4 替换为占位符，结果在本地还原。 |
| 确认 | 默认每次发送前预览并确认。 |
| 密钥 | DPAPI 加密保存；不写日志、不出现在错误信息与请求体中（仅在授权头）。 |
| 错误 | 按状态码映射中文提示（401、402、403、404、429、5xx）；非 JSON 响应体不展示。 |

**威胁与缓解**：

| 风险 | 缓解 |
|---|---|
| 敏感信息外发 | 仅发送摘要；敏感字段始终屏蔽；发送前预览；可替换地址；用户需自行确认符合组织规定。 |
| 密钥泄露 | DPAPI 加密；不落日志；界面仅显示掩码。 |
| 明文传输 | 强制 https（回环例外）。 |
| 模型输出不准确 | 界面注明“仅供参考”；不参与判定；系统提示词要求区分事实与推断。 |

### C9 界面与文案

- 设计系统：统一输入框、下拉框（可编辑，预置 + 历史）、页签、表格、分段按钮、紧凑按钮；表格选中行使用主题色。
- 图标：使用 Segoe MDL2 Assets / Segoe Fluent Icons 字体图标，取代表情符号。
- 文案规范：见 `CLAUDE.md` 的“界面文案规范”。
- 可访问性：图标加文字的控件设置 `AutomationProperties.Name`；列表项类型重写 `ToString()`。
- 设置页分组：常规、抓包与分析、数据与隐私、AI 分析、关于与环境。
- 窗口默认 1360 × 860，最小 1100 × 680，按工作区自动收缩。

## 3. 缺陷修复

| 版本 | 缺陷 | 修复 |
|---|---|---|
| v0.2.0 | DNS/HTTP 测试被名称预解析拦截；非 TCP/UDP 类型被端口校验拦截 | 仅需要 IP 的类型才预解析；端口仅在 TCP/UDP 时校验 |
| v0.2.0 | 结果表检查项一律显示 `TcpConnect` | 按实际类型显示 |
| v0.3.0 | 场景诊断结束后顶栏“运行中”指示不消失；抓包页未接入该指示 | 结束时清除；抓包页接入 |
| v0.3.0 | 抓包到达最长时长后不自动结束 | 到达最长时长后自动停止并分析 |
| v0.3.0 | PowerShell 输出按 OEM 代码页产生中文乱码（路由、防火墙） | 统一设置控制台输出编码为 UTF-8 |

| v0.3.0 | 批量页首次打开时端口包默认落到“不使用端口包” | 默认选“客户端 → AD 域控” |
