# NetFlow 用户手册 v1.0

适用版本：NetFlow v0.3.0。

## 1. 概述

NetFlow 是面向 IT 工程师的网络与服务诊断工具。基本流程：确定测试所用的源网卡 → 输入目标 → 执行检测 → 查看结论与证据 → 导出报告。

### 1.1 结论等级

| 等级 | 含义 |
|---|---|
| 通过 | 观察事实满足所选成功准则。 |
| 警告 | 可用，但存在需要注意的观察（如延迟偏高、证书临近到期）。 |
| 失败 | 有明确的失败事实（如连接被拒绝、协议错误）。 |
| 未确认 | 请求已发出但无反馈，原因无法确认。 |
| 未检查 | 因权限、能力或条件不满足而未执行，结果中说明原因。 |
| 跳过 | 按模板条件或用户操作跳过。 |

### 1.2 解读结果的三条原则

1. **UDP 无应答 = 未确认。** 既不表示端口开放，也不表示端口关闭。
2. **本机无应答 ≠ 防火墙丢包。** 无应答的原因可能是服务未监听、响应被过滤或丢包，本机无法区分。
3. **端口可连接 ≠ 服务可用。** TCP 连通仅表示传输层建立，服务是否可用需要协议级检查。

所有结果都只描述本机视角。需要目标端视角时，请在目标端同步抓包或查看日志。

## 2. 主窗口

- **源网卡**（窗口顶部）：测试从哪块网卡发出。默认选择带默认网关的以太网卡，虚拟网卡、无线和 VPN 网卡排在其后。所选网卡会被保留；网卡断开时自动切换回默认网卡并提示。
- **状态**：最近一次操作的状态信息。
- **运行中指示**：有任务运行时显示，点击可转到对应页面。切换页面不会中断任务。
- **权限**：显示当前是否以管理员身份运行。

### 2.1 源网卡的作用范围

| 检查 | 是否按所选网卡发出 |
|---|---|
| TCP、UDP、DNS、TLS、HTTP、SMTP、SMB、SSH、RDP、NTP、WinRM 的 TCP 连通性检查 | 是（绑定该网卡地址） |
| ICMP（Ping、路径追踪） | 是，仅 IPv4 |
| LDAP 绑定与查询、SQL 登录阶段、WinRM 的 HTTP 请求阶段 | 否（底层接口不支持指定源地址），结果中会注明 |

目标为 IPv6 而所选网卡没有可用 IPv6 地址时，检测不会自动改用其他网卡，而是提示更换源网卡。

## 3. 快速测试

选择测试类型，输入目标，点击“开始测试”（或在目标框中按回车）。

| 类型 | 说明 |
|---|---|
| TCP 端口 | 测试 TCP 连接。端口下拉包含常见服务及数据库端口（SQL Server 1433、MySQL 3306、PostgreSQL 5432、Oracle 1521、Redis 6379、MongoDB 27017 等），也可直接输入。 |
| UDP 端口 | 发送 UDP 探测包。“UDP 测试方式”可选：自动（端口 123 时同时测试 UDP 与 NTP，其他端口仅测原始 UDP）、原始 UDP、NTP 协议（123）、原始 UDP + NTP。 |
| DNS 解析 | 向 DNS 服务器查询 A/AAAA 记录，默认使用源网卡的 DNS 服务器，也可手动指定。NXDOMAIN 表示服务器有响应，但域名不存在。 |
| HTTP/TLS | 默认使用 HTTPS 并检查证书，也可输入完整 URL。 |
| Ping/路径 | 发送 4 次 ICMP Echo 并追踪路径（最多 10 跳）。 |
| NTP | 向目标发送 NTP 请求（UDP 123）。 |

测试完成后，右侧默认显示**测试摘要**（各检查项的结论与判定说明）。选择左侧结果行可查看该项的观察事实、限制与时间线；点击“返回摘要”回到摘要。

超时、目标、DNS 服务器等输入框均为下拉框：可选择预置值，目标类输入还会保留最近使用的记录。

## 4. 场景诊断

1. 在左侧选择场景模板（列表下方显示模板来源、版本与方向）。
2. 输入目标主机；AD 类场景可填写域（用于 SRV/SPN 查询中的 `{domain}`），SQL Server 场景显示“SQL 实例 / 端口”。
3. 需要同时抓包时勾选“同时抓包”（需要管理员权限）。
4. 点击“开始诊断”。

结果区显示统计卡（通过、警告、未确认、失败）、各检查项、事件时间线和诊断证据（含推断、限制、下一步）。点击“导出报告”打开 HTML 报告，报告同时以 JSON、CSV 保存在证据文件夹。

**SQL Server 场景**：默认实例直接测试 TCP 1433，不依赖 SQL Browser。输入数字表示固定端口；输入实例名（如 `SQLEXPRESS`）表示命名实例，先经 Browser 服务（UDP 1434）发现端口。

内置模板为只读，可“保存为新模板”生成副本；自定义模板保存在 `%LOCALAPPDATA%\NetFlow\user-templates.json`，暂无图形化编辑器。

## 5. 抓包分析

### 5.1 抓包方式

| 方式 | 特点 |
|---|---|
| 记录后分析 | 抓包结束后生成 PCAPNG，并自动分析重传、复位、握手失败、DNS、TLS ClientHello、ICMP 错误等；文件可导出。到达最长时长后自动停止并分析。 |
| 实时显示 | 数据包实时输出到列表（时间、方向、来源、目标、协议、信息），右侧显示实时统计。不保存文件；同一数据包在多个网络组件处的重复输出已自动去重。 |

### 5.2 操作

1. 输入过滤目标（IP）。仅抓取与该 IP 相关的流量。
2. 选择抓包方式、最长时长（10–3600 秒）和截断字节数（0 表示完整数据包）。
3. 点击“开始抓包”。抓包需要管理员权限，系统会提示用户账户控制（UAC）。
4. 点击“停止”，或等待到达最长时长。

其他功能：“导入 PCAPNG”分析已有文件；“TShark 深入解析”需要已安装 Wireshark/TShark；“AI 分析”将分析摘要和前 150 条数据包摘要发送给 AI。

### 5.3 说明

- 抓包由本程序以管理员身份启动的独立进程完成，主程序仍以标准权限运行。
- 实时显示列表最多保留 20000 行，超出后统计仍继续。
- 抓包文件保存在 `%LOCALAPPDATA%\NetFlow\evidence\<任务 ID>\capture\`。

## 6. 服务与日志

### 6.1 目标计算机

留空表示本机；输入主机名或 IP 表示远程查询，使用当前 Windows 身份的权限。

### 6.2 远程查询所需端口

| 用途 | 需要目标放行 |
|---|---|
| 事件日志 | TCP 135（RPC 端点映射）、动态 RPC 端口 49152–65535（防火墙规则组“远程事件日志管理”“WMI”） |
| 服务列表 | 同上，另需 TCP 445 |

“检测远程端口”按钮检测目标 TCP 135 与 445 的可达性。动态 RPC 端口无法一次性验证，查询仍失败时请检查目标防火墙。

### 6.3 事件日志筛选

| 条件 | 说明 |
|---|---|
| 日志 | 预置：安全（Security，默认）、系统、应用程序、安装、PowerShell、转发的事件、目录服务、DNS 服务器、DNS 客户端、防火墙、SMB 客户端连接、远程桌面连接；也可输入任意日志名。 |
| 级别 | 全部、严重、错误、警告、信息、详细、错误及以上、警告及以上。 |
| 时间范围 | 不限、最近 1 小时、24 小时、7 天、30 天。 |
| 事件 ID | 可选预置（如 4625 登录失败、4740 账户锁定、7036 服务状态变化），也可输入多个 ID，以逗号分隔。 |
| 条数 | 20、50、100、200、500，或自行输入（最大 2000）。 |

读取安全（Security）日志需要管理员权限，或将当前账户加入 Event Log Readers 组。

## 7. 批量任务

### 7.1 批量检测

1. 在“主机列表”中每行输入一个主机：
   - `host`：按所选端口包展开，对包内每个端口测试；
   - `host:port`：仅测试该 TCP 端口。
2. 选择端口包。
3. 设置并发数与超时，点击“开始检测”。

结果按“主机 × 端口”逐项列出，可随时停止；未执行的项标记为“已取消”。单次最多 2000 项。UDP 端口 123 使用 NTP 协议检测，其他 UDP 端口发送原始 UDP 探测包（结果多为“未确认”）。

### 7.2 内置端口包

| 端口包 | 项数 | 内容 |
|---|---|---|
| 客户端 → AD 域控 | 14 | TCP 53/88/135/389/445/464/636/3268/3269；UDP 53/88/123/389/464 |
| 域控 ↔ 域控（复制） | 16 | 上述端口 + TCP 9389、5722 |
| 文件共享（SMB） | 4 | TCP 445/139；UDP 137/138 |
| 常见数据库 | 7 | TCP 1433/3306/5432/1521/27017/6379；UDP 1434 |
| SQL Server | 2 | TCP 1433；UDP 1434 |
| MySQL / MariaDB | 2 | TCP 3306/33060 |
| PostgreSQL | 1 | TCP 5432 |
| 邮件 | 9 | SMTP/IMAP/POP3 及加密端口、80/443 |
| Web 服务 | 4 | TCP 80/443/8080/8443 |
| 远程管理 | 6 | TCP 22/3389/5985/5986/135/445 |
| DNS 服务 | 2 | TCP/UDP 53 |
| 时间同步（NTP） | 1 | UDP 123 |

### 7.3 自定义端口包

点击“管理端口包”：

- 输入名称、说明和端口列表，每行一项，格式：`tcp/445 SMB 文件共享`、`udp/123 NTP`、`445/tcp`；只写端口号按 TCP；`#` 之后为注释；说明可省略。
- “保存”覆盖当前自定义端口包，“另存为”创建新包，“删除”移除自定义端口包。
- 内置端口包为只读，可修改后另存为自定义端口包。名称不能与内置端口包重复。

自定义端口包保存在本地数据库中，重启后仍然存在。

### 7.4 持续监测

按固定间隔（30–600 秒）对单个 `host:port` 执行 TCP 检测，以色块显示采样结果。休眠、断网等造成的采样缺口单独统计，不计为目标故障。

## 8. AI 分析

### 8.1 配置

“设置 → AI 分析”：

1. 勾选“启用 AI 分析”。
2. 服务商 DeepSeek，API 地址默认 `https://api.deepseek.com`（必须使用 https，仅本机回环地址允许 http）。
3. 输入 API Key，点击“保存密钥”。密钥经 Windows 数据保护 API（当前用户）加密后保存在本机数据库，不写入日志或报告。
4. 点击“获取模型列表”选择模型：`deepseek-flash`（响应快，默认）或 `deepseek-v4-pro`（能力更强、耗时更长）。
5. 点击“测试连接”确认可用。

| 选项 | 说明 |
|---|---|
| 推理强度 | 低（默认）、高、最高、不指定。强度越高，分析越深入，耗时也越长。 |
| 超时（秒） | 单次请求的超时时间。 |
| 每次发送前预览并确认 | 默认开启。 |
| 发送前将 IPv4 地址替换为占位符 | 开启后，发送内容中的 IPv4 地址被替换为 IP-1、IP-2…，返回结果在本地还原。 |

### 8.2 使用

在“快速测试”“场景诊断”“抓包分析”页面点击“AI 分析”。窗口显示将发送的内容（已脱敏），可补充问题，点击“确认发送并分析”。结果包含结论摘要、关键证据、可能原因（按可能性排序）、建议的下一步排查和需要补充的信息。

### 8.3 发送内容与隐私

- 仅发送本次结果的摘要文本：目标、源网卡、检查项结论及观察事实、系统发现；抓包为分析摘要和前 150 条数据包摘要。总长度不超过 14000 字符。
- 不发送 PCAPNG 文件。
- 密码、令牌、Authorization 等敏感字段始终被屏蔽，无法关闭。
- 内容将发送至所配置的 API 地址。请确认符合所在组织的数据外发规定。
- AI 结论仅供参考，请结合证据核实。

### 8.4 常见问题

| 现象 | 处理 |
|---|---|
| 提示 API Key 无效（401） | 在设置中重新输入密钥。 |
| 提示账户余额不足（402） | 到服务商后台充值。 |
| 结果被截断 | 降低推理强度，或缩小分析范围后重试。 |
| 密钥无法解密 | 密钥由其他 Windows 账户或计算机保存，请重新输入。 |

## 9. 设置

| 分组 | 内容 |
|---|---|
| 常规 | 默认超时、批量默认并发数；恢复默认源网卡。 |
| 抓包与分析 | 默认抓包方式、最长时长、截断字节数；Pktmon 与 TShark 检测；权限说明。 |
| 数据与隐私 | 报告脱敏开关；留存天数与“立即清理超期记录”；打开数据文件夹；清除输入历史。 |
| AI 分析 | 见第 8 章。 |
| 关于与环境 | 版本、权限、数据库与证据文件夹位置、数据库状态。 |

设置修改后自动保存。留存清理不会自动执行：仅在确认“立即清理超期记录”后，删除超过留存天数的诊断记录和对应证据文件夹（仅限任务 ID 命名的文件夹）。

## 10. 数据与文件

| 位置 | 内容 |
|---|---|
| `%LOCALAPPDATA%\NetFlow\netflow.db` | SQLite：诊断记录、设置、端口包、输入历史 |
| `%LOCALAPPDATA%\NetFlow\evidence\<任务 ID>\` | 报告（`report.html`、JSON、CSV）、抓包文件 |
| `%LOCALAPPDATA%\NetFlow\user-templates.json` | 自定义场景模板 |

数据库不可用时，诊断功能不受影响，历史记录暂不可用，设置与端口包仅在本次运行期间有效。

## 11. 故障排除

| 现象 | 可能原因与处理 |
|---|---|
| 无法抓包 | 未获得管理员权限；或 Pktmon 不可用（“设置 → 抓包与分析”可重新检测）。 |
| 提示“没有可用的源网卡” | 没有在线且有可用地址的网卡，请检查网络连接。 |
| 远程事件日志或服务查询失败 | 使用“检测远程端口”；确认目标放行 TCP 135、动态 RPC 端口和 TCP 445，且账户有权限。 |
| 读取 Security 日志无权限 | 以管理员身份运行，或加入 Event Log Readers 组。 |
| UDP 测试显示“未确认” | 属正常结果，见 1.2 节；可改用对应协议的检查（如 NTP）。 |

## 12. 已知限制

- 自定义场景模板尚无图形化编辑器，需直接编辑 `user-templates.json`。
- 命令行（CLI）为基础版，暂不支持源网卡选择和端口包。
- AI 分析当前仅支持 DeepSeek。
- 动态 RPC 端口（49152–65535）的可达性无法在“检测远程端口”中验证。
- 本机未加域时，Kerberos 单点登录相关检查仅验证到“显式凭据”级别。
